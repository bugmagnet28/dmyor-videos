# dmyor-videos

The video studio for [Dmyor](https://dmyor.com): short reels for Instagram, YouTube Shorts and X, all on **@becauseidmyor**. One goal: grow followers with reels that are genuinely useful. This repo holds the video styles (skills), the daily agent, the rules, the analytics and every reel we have made.

If you read one file first, read **[studio/OWNER-RULES.md](studio/OWNER-RULES.md)**. It lists every decision the owner has made and overrides everything else here.

## How a reel gets made

1. **Idea and script.** From `studio/idea-bank.md` and what analytics says works. Write for the ear: staged hook, explain, turn, land, outro. Logical examples only. End with the value close (see OWNER-RULES section 2). Score it against the quality bar.
2. **Pick a style** (table below). Default is `animated-illustration-explainer`.
3. **Build** with the style's own script, for example `python3 .claude/skills/animated-illustration-explainer/scripts/make_reel.py reels/<slug> --record`. A reel folder holds its config (scenes, narration, cues), the HTML that draws it, and the render.
4. **Voice.**
   - Drafts use the local Kokoro voice (`am_eric`).
   - **Final voice is ElevenLabs Adam, generated by hand** (v3 audio tags, one take). Paste `reels/<slug>/narration-elevenlabs-v3.txt` into ElevenLabs, save the mp3 as `inbox/audio/<slug>.mp3`, then re-time the picture to the take (`make_reel.py --vo`). For the pixel film use `reels/pixel-book/vo_external.py`, which cuts only in real pauses and keeps the take to its natural end.
   - Free voices tested and rejected: Kokoro (flat), Qwen3-TTS voice design (closest, still darker than Adam).
5. **Check it like a viewer.** Pull frames (`studio/tools/frames.sh <mp4> 0 0.5 1 2 ...`) and look at them: finished frame 0, nothing cut off, nothing frozen. Check the mix with `tools/earshot` (`earshot measure`, `earshot ab`, `earshot critique`). Never use its `llm --yes-upload`.
6. **Package.** `ready-to-post/<date>-<slug>/video.mp4` (under 10 MB for browser upload) and `post.md` with the captions for each platform, hashtags, post time and the experiment it tests. Add it to `studio/post-queue.md`.
7. **Approval.** The owner approves a batch before anything is scheduled.
8. **Schedule** on all three platforms at the same time (steps below). Tick it in `post-queue.md`.
9. **Register and learn.** `python3 analytics/scripts/record.py content ...` for each post (set `hook_type` from the fixed list in video.md step 9b), record metrics at about 24 h, 48 h and 7 days, rebuild with `analytics/.venv/bin/python analytics/scripts/build.py`, and rebuild the library with `python3 studio/tools/reel_library.py`.

## Styles (skills in `.claude/skills/`)

| Style | Use for | Status |
|---|---|---|
| `animated-illustration-explainer` | Methods and ideas with worked examples, one line-art scene per thought, Graphite & Sage palette, object sound effects, value close | Default. Meets every rule |

The reel library's "Made with" column shows which of these built each past reel.

## Sound

- Default effects are synthesised (`.claude/skills/animated-illustration-explainer/scripts/sfx.py`): audible, objects sound like themselves, no sound on every cut, no suspense risers.
- Real recordings are allowed from Openverse, **CC0 only**: `python3 studio/tools/fetch_sfx.py search "page turn"` then `get ... --name page`. Files and licence log live in `studio/sfx-library/`.
- Music is an open decision. Explainers have none; cinematic films have a composed score.

## Posting (scheduled from the browser)

Captions are short and about what Dmyor does. No em dashes anywhere. "Link in bio". Same 1080x1920 file everywhere, under 10 MB, at the same times (typical IST slots 09:30, 13:00, 16:30, 19:30).

- **Instagram** (instagram.com, Create, Post): upload, crop to 9:16, Next, Next, caption, turn on **Schedule content**, pick date and time (needs **20 minutes or more** lead time), open Advanced settings and turn on **Hide like and view counts**, Schedule. At most **5 scheduling flows per browser session** and no bulk insight scraping: the account was locked once. Instagram web has no archive, only delete.
- **X** (x.com compose): attach the video and **wait until it shows Ready** before scheduling (a post scheduled too early went out without its video), set the schedule date and time, Schedule. Check `x.com/compose/post/unsent/scheduled` afterwards to confirm each post has its video.
- **YouTube Studio** (upload): title `<hook> #Shorts`, description with the caption and `dmyor.com`, "No, it's not made for kids", then Visibility, Schedule. **The time zone resets every time: set it to (GMT+0530) before choosing the time.** Find fields by label, not by coordinates (the layout shifts after upload). Description links are not clickable until phone verification is done.
- If anything errors, stop and ask. Do not retry repeatedly.

## Daily agent

A LaunchAgent (`com.dmyor.video`) runs [studio/run.sh](studio/run.sh) at 11:00 (the Mac must be on). It follows the cycle in `.claude/agents/video.md`: load memory, ingest metrics, learn, plan 3-5 reels, build, check frames, package, ask, report. It never posts, logs in anywhere or emails anyone except the owner. Its only memory is what is written in `studio/`, `reels/` and `inbox/`.

| To | Do |
|---|---|
| Pause it | `touch studio/PAUSE` (delete to resume) |
| Run it now | `studio/run.sh` |
| Give it a voiceover | Save the mp3 in `inbox/audio/` |
| Give it numbers | Insight screenshots into `inbox/metrics/` |
| Tell it something | `inbox/notes.md` |

Its current limits: it has no browser, so it cannot read fresh metrics or schedule. The interactive Claude Code session does that.

## Ground rules

- Real graphics in every reel, never text only. Classy motion (ease in and out, no bounce). Never a frozen screen. Finished frame 0.
- Honest: no invented numbers, studies or testimonials. Dmyor features are mostly locked: say "Full features are releasing soon", never "the planner".
- No copyrighted music or footage. Photos only if CC0.
- Never create accounts or enter passwords for the owner. Never edit the Dmyor app code (`~/Documents/Dmyor`, read-only from here).
- Videos, audio and virtual environments are not committed (see `.gitignore`).
